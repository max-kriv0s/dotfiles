# DevSecOps — Шпаргалка

Инструменты статического анализа безопасности: что установлено, как запускать,
что искать. Установка — через [packages](../packages/macos/Brewfile), раздел
«Dev: линтеры и безопасность».

---

## Что чем проверяется

| Слой | Инструмент | Где запускается |
| ---- | ---------- | --------------- |
| Зависимости проекта (CVE) | trivy | вручную, CI |
| Docker-образы | trivy | вручную, CI |
| IaC: Dockerfile, compose, terraform, k8s | trivy | вручную, CI |
| Dockerfile: best practices | hadolint | в nvim при сохранении |
| Shell-скрипты | shellcheck | в nvim при сохранении |
| Terraform | tflint | в nvim при сохранении |
| YAML-синтаксис | yamllint | в nvim при сохранении |
| GitHub Actions | actionlint | в nvim при сохранении |

Разделение простое: **быстрые линтеры** работают в редакторе на каждое
сохранение, **trivy** запускается руками или в CI — он тяжёлый и ему нужна
база уязвимостей.

---

## Trivy

Сканер от Aqua Security. Умеет искать уязвимые зависимости, ошибки в
конфигурации инфраструктуры и утёкшие секреты.

### Сканирование проекта

```bash
trivy fs .                              # текущий каталог: зависимости, секреты, IaC
trivy fs --severity HIGH,CRITICAL .     # только важное
trivy fs --scanners vuln .              # только уязвимости зависимостей
trivy fs --scanners secret .            # только секреты
trivy fs --scanners misconfig .         # только ошибки конфигурации
```

Находит и разбирает `package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`,
`go.sum`, `requirements.txt`, `poetry.lock`, `uv.lock`, `Gemfile.lock` и
десятки других манифестов.

### Docker-образы

```bash
trivy image nginx:alpine                # образ из реестра
trivy image my-app:latest               # локально собранный
trivy image --severity CRITICAL my-app  # только критичное
trivy image --ignore-unfixed my-app     # скрыть то, что ещё не исправлено апстримом
```

`--ignore-unfixed` — важный флаг на практике: без него список забит
уязвимостями, для которых патча пока нет, и полезное в нём теряется.

### Инфраструктура как код

```bash
trivy config .                          # Dockerfile, compose, terraform, k8s, helm
trivy config --severity HIGH .
```

Проверяет не синтаксис, а конфигурацию с точки зрения безопасности: контейнер
от root, открытый наружу порт, бакет без шифрования, отсутствие лимитов
ресурсов.

### Секреты

```bash
trivy fs --scanners secret .
trivy repo https://github.com/user/repo  # удалённый репозиторий без клонирования
```

Ищет токены, ключи и пароли по шаблонам известных сервисов.

### Для CI

```bash
trivy fs --exit-code 1 --severity HIGH,CRITICAL .
```

`--exit-code 1` заставляет команду завершиться с ошибкой при находках — так
сборка падает, а не проходит с предупреждением в логе.

### Исключения

Файл `.trivyignore` в корне проекта:

```
# уязвимость в транзитивной зависимости, эксплуатации нет, ждём обновления
CVE-2023-12345

# конкретное правило проверки конфигурации
AVD-DS-0002
```

Лучше указывать причину комментарием — иначе через полгода никто не вспомнит,
почему исключение появилось.

### База уязвимостей

```bash
trivy --download-db-only     # обновить базу заранее
trivy clean --all            # очистить кэш
```

База (~200 МБ) скачивается при первом запуске в `~/Library/Caches/trivy` и
дальше обновляется инкрементально.

## Проверка окружения nvim

Языковые серверы и инструменты Mason — это обычные npm- и Go-пакеты, их тоже
имеет смысл проверять:

```bash
trivy fs ~/.local/share/nvim-next/mason    # языковые серверы, линтеры, форматтеры
trivy fs ~/.local/share/nvim-next/lazy     # плагины
```

У плагинов на Lua манифестов зависимостей нет, поэтому уязвимости там искать
нечем — сканирование найдёт разве что случайно закоммиченные секреты. Защита
от подмены кода здесь другая: `lazy-lock.json` фиксирует точные коммиты, и
обновление происходит только по явной команде.

## Чего пока нет

Инструменты, которые имеет смысл добавить по мере надобности:

| Инструмент | Зачем | Когда добавлять |
| ---------- | ----- | --------------- |
| gitleaks | поиск секретов в истории git, а не только в рабочей копии | когда появится риск, что секрет уже закоммичен |
| semgrep | поиск уязвимых паттернов в коде по правилам: SQL-инъекции, небезопасная десериализация | для AppSec-задач, требует настройки набора правил |
| checkov | глубокая проверка IaC, правил больше чем у trivy | если terraform станет основным рабочим инструментом |

Оба первых имеет смысл ставить в pre-commit, а не в редактор: они медленные и
их место — на границе коммита, а не на каждое нажатие `:w`.
