# История команд и zoxide — Шпаргалка

Что хранит историю в терминале, где это настроено и как чистить.

- **История команд** — сам zsh, файл `~/.zsh_history`
- **История переходов по каталогам** — zoxide, база `~/Library/Application Support/zoxide/db.zo` (macOS)

---

## История команд zsh

### Где настроено

`zsh/.zshrc`, блок `# History`:

| Настройка | Что делает |
| --------- | ---------- |
| `HISTSIZE=1000` | сколько команд держать в памяти сессии |
| `SAVEHIST=$HISTSIZE` | сколько команд хранить в файле — старые вытесняются новыми |
| `HISTFILE=~/.zsh_history` | файл истории |
| `setopt appendhistory` | дописывать в файл, а не перезаписывать |
| `setopt sharehistory` | общая история для всех открытых терминалов |
| `setopt hist_ignore_space` | команда с пробелом в начале не сохраняется |
| `setopt hist_ignore_all_dups` | при повторе старая копия команды удаляется |
| `setopt hist_save_no_dups` | не писать дубликаты в файл |
| `setopt hist_ignore_dups` | не сохранять повтор подряд |
| `setopt hist_find_no_dups` | не показывать дубликаты при поиске |

`HISTDUP=erase` ни на что не влияет: такой переменной в zsh нет, дубликаты убирают опции `hist_*`.

Срока хранения по времени нет — только лимит по количеству. Из-за удаления дубликатов 1000 — это 1000 уникальных команд.

### Поиск

| Клавиши | Действие |
| ------- | -------- |
| `Ctrl+R` | поиск по истории через fzf |
| `Ctrl+P` / `Ctrl+N` | предыдущая / следующая команда с тем же началом |

### Как не сохранять лишнее

| Способ | Как |
| ------ | --- |
| Разово | начать команду с пробела: ` export TOKEN=...` |
| Всегда по шаблону | добавить в `.zshrc`: `HISTORY_IGNORE="(*token*\|*password*\|*secret*)"` |

### Как чистить

| Задача | Как |
| ------ | --- |
| Удалить одну команду | закрыть остальные терминалы, удалить строку в `~/.zsh_history` редактором, открыть новый терминал |
| Очистить всё | `: > ~/.zsh_history`, затем перезапустить shell |
| Держать меньше | уменьшить `HISTSIZE` |

Остальные терминалы закрывать обязательно: из-за `sharehistory` они перезапишут файл своей копией истории.

### Аналитика

Почти нет: дубликаты удаляются, поэтому частоту команд не посчитать, а время вызова не хранится. Время включается опцией `setopt extended_history`.

## zoxide

Запоминает каталоги, в которые переходишь, и прыгает в них по части имени. Подключён в `zsh/.zshrc`:

```zsh
eval "$(zoxide init --cmd cd zsh)"
```

`--cmd cd` — zoxide подменяет `cd`, отдельной команды `z` нет.

### Переходы

| Команда | Действие |
| ------- | -------- |
| `cd foo` | перейти в самый частый каталог, в пути которого есть `foo` |
| `cd foo bar` | то же, по нескольким словам |
| `cdi foo` | выбрать каталог из списка через fzf |
| `cd path` | обычный переход, если `path` существует |

### Управление базой

| Команда | Действие |
| ------- | -------- |
| `zoxide query -ls` | все каталоги с весом |
| `zoxide query -ls foo` | каталоги, подходящие под `foo` |
| `zoxide query -i` | выбрать каталог интерактивно |
| `zoxide remove path` | удалить каталог из базы |
| `zoxide edit` | интерактивное редактирование: удалить, повысить или понизить вес |
| `zoxide add path` | добавить каталог или повысить вес |

### Настройки

Задаются переменными окружения, в dotfiles сейчас не заданы — работают значения по умолчанию.

| Переменная | Что делает |
| ---------- | ---------- |
| `_ZO_EXCLUDE_DIRS` | каталоги, которые не запоминать, через `:` — например `$HOME:$HOME/private/*` |
| `_ZO_MAXAGE` | предел суммарного веса: при превышении веса снижаются, редкие записи удаляются |
| `_ZO_DATA_DIR` | где хранить базу |
| `_ZO_ECHO` | `1` — печатать каталог перед переходом |
| `_ZO_FZF_OPTS` | флаги fzf для интерактивного выбора |
| `_ZO_RESOLVE_SYMLINKS` | `1` — сохранять реальные пути вместо симлинков |

### Как чистится

- Сама: при превышении `_ZO_MAXAGE` редкие каталоги выпадают, несуществующие удаляются при обращении
- Вручную: `zoxide remove path` или `zoxide edit`
- Полностью: удалить `~/Library/Application Support/zoxide/db.zo`
