# Lazygit — git в терминале

Терминальный клиент git: вместо набора команд — панели, по которым ходишь
клавишами. Удобен там, где текстовый git требует много шагов: разложить
изменения по коммитам, переписать историю, разобраться в ветках.

Ставится через Homebrew (`brew "lazygit"` в Brewfile), настройки —
`lazygit/.config/lazygit/config.yml` в этом репозитории.

Из Neovim открывается по `Space lg` (см. [nvim/README.md](nvim/README.md)), из терминала — `lazygit`.

---

## Главное правило

`?` показывает **все** клавиши текущей панели. Их много, запоминать весь
список не нужно: открыли панель, нажали `?`, нашли нужное. Ниже — только то,
что используется каждый день.

`q` — выход, `Esc` — шаг назад.

---

## Панели

Слева пять панелей, переключение цифрами `1`–`5` или `Tab`:

| Клавиша | Панель | Зачем |
|---|---|---|
| `1` | Status | ветка, состояние репозитория |
| `2` | Files | изменённые файлы — основная рабочая панель |
| `3` | Branches | ветки, переключение, слияние |
| `4` | Commits | история, переписывание коммитов |
| `5` | Stash | отложенные изменения |

Справа — содержимое: дифф выбранного файла, список коммитов ветки и так далее.

`+` и `_` меняют размер правой панели. Пригодится: дифф настроен в две
колонки, и в узкой панели они не помещаются.

---

## Дифф как в терминале

Дифф внутри lazygit показывает delta — тот же инструмент, что у `git diff`
в обычном терминале. Две колонки «было / стало», номера строк, подсветка
синтаксиса. Настройки delta не дублируются: они берутся из секции `[delta]`
в `git/.config/git/config`, так что вид везде одинаковый.

Если две колонки кажутся тесными — `+` расширит панель.

## Файлы: панель `2`

| Клавиша | Действие |
|---|---|
| `Space` | добавить файл в индекс / убрать из индекса |
| `a` | то же для всех файлов сразу |
| `Enter` | построчный режим — см. ниже |
| `d` | отбросить изменения (спросит, какие именно) |
| `c` | закоммитить то, что в индексе |
| `C` | то же, но сообщение писать в редакторе |
| `A` | добавить изменения к последнему коммиту |
| `s` | отложить изменения в stash |
| `e` | открыть файл в редакторе — см. отдельный раздел |
| `i` | добавить в `.gitignore` |

### Построчный режим

`Enter` на файле открывает его дифф построчно. Здесь коммит собирается из
кусков: берём в индекс только то, что относится к задаче, остальное
остаётся в рабочем каталоге.

| Клавиша | Действие |
|---|---|
| `↑` / `↓` | по строкам |
| `v` | начать выделение диапазона |
| `Space` | взять в индекс строку или выделенное |
| `d` | отбросить строку или выделенное |
| `Tab` | переключиться между «в индексе» и «не в индексе» |
| `Esc` | назад к списку файлов |

## Открыть файл в Neovim

Редактировать внутри lazygit нельзя — это просмотрщик. Но `e` на файле
открывает его в редакторе, и настроено так, чтобы файл попадал **в тот же
Neovim**, из которого lazygit запущен, новой вкладкой.

```
e               → файл открылся вкладкой в nvim позади lazygit
q               → закрыть lazygit
Space tn        → перейти на вкладку с файлом
```

Работает это через `os.edit` в `config.yml`: внутри встроенного терминала
Neovim выставляет переменную `$NVIM`, а `nvim --server "$NVIM" --remote-tab`
отправляет команду в уже запущенную сессию. Без этой настройки `e` запустил
бы **вторую** копию Neovim прямо внутри окна lazygit — со своими буферами и
своим LSP, что почти всегда не то, чего хочется.

Если lazygit запущен из обычного терминала, `$NVIM` пуст и открывается
обычный `nvim` — настройка это учитывает.

## Ветки: панель `3`

| Клавиша | Действие |
|---|---|
| `Space` | переключиться на ветку |
| `n` | создать ветку от текущей |
| `d` | удалить ветку |
| `M` | влить выбранную ветку в текущую |
| `r` | перебазировать текущую ветку на выбранную |
| `f` | подтянуть ветку без переключения на неё |

---

## Коммиты: панель `4`

| Клавиша | Действие |
|---|---|
| `Enter` | посмотреть файлы коммита |
| `r` | изменить сообщение |
| `d` | удалить коммит |
| `s` | склеить с коммитом ниже |
| `f` | то же, но сообщение берётся от нижнего |
| `e` | начать интерактивный rebase с этого коммита |
| `t` | создать коммит, отменяющий выбранный |

Всё это переписывает историю. Правило прежнее: пока коммиты не отправлены
в удалённый репозиторий — можно свободно, после `push` — только если ветка
ваша и никто на неё не опирается.

---

## Обмен с удалённым репозиторием

| Клавиша | Действие |
|---|---|
| `p` | pull |
| `P` | push |
| `f` | fetch |

---

## Если что-то пошло не так

`z` отменяет последнее действие, `Ctrl+z` возвращает обратно. Lazygit ведёт
собственный журнал операций поверх reflog, так что откатить можно даже
неудачный rebase.

Посмотреть, какие именно команды git выполняет lazygit, — `@`. Полезно, пока
привыкаете: видно, что за клавишей стоит обычный git.

---

## Что lazygit не умеет

Редактирования внутри диффа нет — и его нет ни в одном терминальном клиенте
git (ни в `gitui`, ни в `tig`, ни в инструментах ревью вроде `tuicr`). Все
они открывают внешний редактор.

Если нужно именно «смотрю дифф и тут же правлю» — это делается в Neovim:
`Space hd` открывает сравнение с индексом двумя буферами, и правый буфер
обычный, редактируемый.
