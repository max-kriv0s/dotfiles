# Neovim — сценарии работы

Не справочник клавиш (он в [README.md](README.md)), а типовые рабочие ситуации:
что делает разработчик и какими клавишами это складывается в поток.

Читать можно по одному сценарию: освоили — переходите к следующему.

---

## 1. Начать работу над задачей

**Задача:** открыть проект и найти нужный файл, не вспоминая его путь.

```
cd ~/projects/my-app
nv
<leader>ff        → список файлов, набрать часть имени
Enter           → открыть
```

`<leader>ff` ищет не по началу имени, а по любым буквам подряд: `usrctl` найдёт
`user/controller.ts`. Это быстрее, чем ходить по дереву.

Дерево нужно, когда вы не знаете, что искать, — посмотреть структуру:

```
<leader>ee        → дерево слева
j / k           → вверх-вниз
l               → войти в папку или открыть файл
h               → свернуть
q               → закрыть дерево
```

**Что запомнить:** дерево — для обзора незнакомого проекта, `<leader>ff` — для
работы в знакомом. Опытные пользователи деревом почти не пользуются.

## 2. Разобраться в незнакомом коде

**Задача:** пришла задача «почини расчёт скидки», вы не знаете, где он.

```
<leader>fw             → поиск по тексту проекта
discount             → набрать
Ctrl+j / Ctrl+k      → листать результаты, снизу предпросмотр
Enter                → открыть нужный
```

Нашли функцию `calculateDiscount`. Теперь понять, как она устроена и кто её
зовёт:

```
gd        → прыгнуть к определению функции
K         → всплывающее окно с сигнатурой и документацией
gR        → список всех мест, где функция используется
Ctrl+O    → вернуться назад
```

`gR` — главный инструмент чтения чужого кода. Он показывает **реальные**
использования: языковой сервер понимает область видимости и не покажет
одноимённую функцию из другого модуля. Текстовый поиск так не умеет.

Провалились на три уровня вглубь — `Ctrl+O` трижды вернёт вас в начало.

**Что запомнить:** `<leader>fw` чтобы найти зацепку, дальше `gd` и `gR` чтобы
ходить по связям, `Ctrl+O` чтобы не потеряться.

## 3. Исправить и сохранить

**Задача:** поменять логику внутри функции.

```
]f                → прыжок к следующей функции
vif               → выделить её тело
c                 → заменить выделенное, сразу режим вставки
jj                → выйти в обычный режим
:w                → сохранить
```

При сохранении файл форматируется сам — prettier для js/ts, ruff для Python,
gofmt для Go. Отступы и кавычки приводить в порядок вручную не нужно.

Если форматирование в этот раз мешает (например, правите чужой файл и не
хотите шумного диффа):

```
<leader>uf          → выключить автоформат
:w                → сохранить как есть
<leader>uf          → включить обратно
```

**Что запомнить:** `vif` / `vaf` работают в любом языке с установленным
парсером — не нужно выделять построчно.

## 4. Переименовать сущность во всём проекте

**Задача:** `getUser` назвать `fetchUser` везде, включая импорты в других файлах.

```
gd                → встать на определение
<leader>rn          → ввести новое имя
Enter
```

Переименование делает языковой сервер, а не текстовая замена. Он правит только
настоящие использования и не трогает совпадения в строках, комментариях и
одноимённые методы других классов.

Файлы, которые при этом изменились, останутся открытыми как буферы. Сохранить
все разом:

```
:wa
```

**Что запомнить:** `<leader>rn` вместо `:%s/getUser/fetchUser/g` — вторая команда
работает только в текущем файле и ломает строки-совпадения.

## 5. Разобрать ошибки

**Задача:** файл подсвечен ошибками, надо пройтись по ним.

```
]d                → прыжок к следующей ошибке
<leader>d           → полный текст: что именно не так и кто это сказал
<leader>ca          → список быстрых исправлений
Enter             → применить выбранное
```

`<leader>ca` умеет многое: добавить недостающий импорт, привести тип, убрать
неиспользуемую переменную, вынести значение в константу. Всё, что редактор
может починить сам, — здесь.

Посмотреть всё сразу:

```
<leader>D         → все ошибки текущего файла списком
<leader>fd          → все ошибки проекта
```

**Что запомнить:** источник сообщения виден в окне `<leader>d` — это либо
языковой сервер (ошибка типов), либо линтер (нарушение правил стиля).

## 6. Работать с несколькими файлами

**Задача:** держать перед глазами тест и код одновременно.

```
<leader>ff          → открыть первый файл
<leader>sv          → разделить окно вертикально
<leader>ff          → во втором окне открыть другой файл
Ctrl+h / Ctrl+l   → переключаться между окнами
<leader>sx          → закрыть окно, которое больше не нужно
```

Открытые файлы живут как буферы независимо от окон:

```
Tab / Shift+Tab   → переключиться на следующий или предыдущий
<leader>fb          → список открытых, с поиском
<leader>bx          → закрыть текущий
<leader>bo          → закрыть все, кроме текущего
```

Когда буферов накопилось три десятка — `<leader>bo` и продолжаете с чистого
листа.

**Что запомнить:** окно — это область экрана, буфер — открытый файл. Закрыли
окно — файл остался открытым.

---

## 7. Запустить что-нибудь, не выходя из редактора

**Задача:** поднять dev-сервер и смотреть его вывод рядом с кодом.

```
Ctrl+\            → терминал снизу
npm run dev       → запустить
Ctrl+\            → спрятать, сервер продолжает работать
Ctrl+\            → вернуться и посмотреть вывод
```

Терминал именно прячется, а не закрывается: процесс не прерывается. Можно
держать несколько:

```
<leader>t1          → терминал 1 — dev-сервер
<leader>t2          → терминал 2 — тесты
<leader>t3          → терминал 3 — команды на ходу
```

Внутри терминала:

```
jj или Esc        → выйти в обычный режим, чтобы листать вывод
i                 → вернуться к вводу команд
Ctrl+h/j/k/l      → перейти в соседнее окно
```

**Что запомнить:** `Ctrl+\` — один и тот же переключатель в обе стороны.
Закрыть насовсем — `exit` внутри терминала.

## 8. Заменить по всему проекту

**Задача:** заменить строку во всех файлах, где она встречается.

```
<leader>fw          → найти все вхождения
Tab               → отметить нужные результаты
Alt+q             → отправить отмеченные в quickfix-список
:cdo s/старое/новое/g | update
```

Последняя команда выполняет замену в каждом файле из списка и сразу сохраняет.

Это мощно и опасно одновременно — перед `:cdo` стоит убедиться, что в списке
только то, что нужно. Для кода почти всегда лучше `<leader>rn`: он понимает
структуру, а не буквы.

**Что запомнить:** quickfix — это список мест в проекте, по которому можно
пройтись командой. Открывается через `:copen`, навигация `:cnext` / `:cprev`.

## 9. Поправить файлы, не открывая их

**Задача:** переименовать несколько файлов, создать папку, разложить модули.

```
-                 → открыть каталог текущего файла как обычный буфер
cw                → переименовать файл под курсором
o                 → новая строка = новый файл
utils/            → строка со слэшем = новая папка
dd                → удалить файл
:w                → применить, подтвердить список операций
```

Каталог здесь — обычный текст, поэтому работает всё: визуальный режим,
множественная правка, отмена через `u` до сохранения.

**Что запомнить:** ничего не происходит до `:w`. Пока не сохранили — это
просто текст в буфере.

---

## 10. Посмотреть свои изменения и закоммитить

**Задача:** день закончился, надо понять, что наменял, и разложить это по коммитам.

Сначала — по текущему файлу, не выходя из него. Слева от номеров строк стоят
значки: `+` строка добавлена, `~` изменена, `-` что-то удалено.

```
]h                → прыжок к следующему изменению
<leader>hp          → показать, что именно изменилось
<leader>hs          → взять этот блок в индекс
<leader>hr          → или откатить, если это был мусор
```

Значки показывают разницу **с индексом**, а не с последним коммитом. Поэтому
после `<leader>hs` значок пропадает: для gitsigns изменение уже учтено. Увидеть
разницу с коммитом — `<leader>hD`.

Дальше — по всему проекту:

```
<leader>lg          → lazygit
2                 → панель файлов
↑ / ↓             → по файлам, справа дифф в две колонки
Space             → файл целиком в индекс
Enter             → или построчно: v выделить, Space взять
c                 → написать сообщение, Enter — коммит
P                 → отправить
q                 → выйти
```

**Перейти к файлу, который смотрите в диффе:**

```
e                 → откроется вкладкой в этом же nvim
q                 → закрыть lazygit
<leader>tn          → перейти на вкладку с файлом
```

Это отдельно настроено в `lazygit/.config/lazygit/config.yml`: без настройки
`e` запустил бы вторую копию nvim внутри окна lazygit.

**Что запомнить:** `<leader>hp` — быстро глянуть одно изменение, `<leader>lg` —
собрать коммит целиком. Подробности по lazygit — в [lazygit.md](lazygit.md).

## Что дальше

Когда описанное станет привычным, стоит освоить:

- **макросы** — `qa` записать, `q` остановить, `@a` повторить: для
  однотипных правок в десятке мест;
- **регистры** — `"ay` скопировать в регистр `a`, `"ap` вставить: несколько
  буферов обмена одновременно;
- **marks** — `ma` поставить метку, `` `a `` вернуться: закладки внутри файла;
- **`:h`** — встроенная справка, в ней есть ответ почти на любой вопрос.
