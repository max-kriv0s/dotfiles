# Neovim — настройка и обслуживание

Как поменять конфиг, обновить плагины, поставить языковой сервер и что делать,
когда что-то сломалось. Состав сборки — в [plugins.md](plugins.md).

---

## Где что лежит

```
nvim/.config/nvim/
├── init.lua              точка входа, подключает модули по порядку
├── lua/core/             настройки без плагинов
│   ├── options.lua       опции редактора
│   ├── keymaps.lua       сочетания клавиш
│   ├── autocmds.lua      автоматические действия по событиям
│   ├── filetypes.lua     распознавание compose, gitlab-ci, ansible, helm
│   ├── lang.lua          дубли маппингов для русской раскладки
│   ├── lazy.lua          запуск менеджера плагинов
│   └── colorscheme.lua   подхват темы из ~/.config/theme
├── lua/plugins/          по файлу на плагин
│   ├── lsp/              языковые серверы и mason
│   └── themes/           темы
├── lsp/                  настройки отдельных серверов
└── colors/               наша тема coolnight
```

Служебные каталоги вне репозитория:

| Путь | Что внутри |
| --- | --- |
| `~/.local/share/nvim` | плагины и всё, что ставит mason |
| `~/.local/state/nvim` | состояние, сессии, история |
| `~/.cache/nvim` | кеш |

Их можно удалить в любой момент — восстановятся при следующем запуске.

## Применить изменения

| Что поменяли | Что сделать |
| --- | --- |
| `core/keymaps.lua`, `core/options.lua` | `:source %` в открытом файле |
| `lua/plugins/*.lua` | перезапустить nvim или `:Lazy reload имя-плагина` |
| состав плагинов | `:Lazy sync` |

Правка в файле плагина через `:source` обычно не срабатывает: lazy.nvim уже
выполнил его конфигурацию один раз и повторно не выполняет.

## `:e!` — перечитать файл с диска

> **Важно:** `:e!` выбрасывает всё, что набрано в буфере, и читает файл заново.
> Несохранённое пропадает без предупреждения.

Буфер — копия файла в памяти. Пока вы не сохранились, копия и файл на диске
могут разойтись: файл изменил git при `checkout`, скрипт или другой человек.
`:w` в этот момент затрёт чужие правки вашей версией.

| Команда | Что делает |
| --- | --- |
| `:e` | перечитать; откажется, если есть несохранённые правки |
| `:e!` | перечитать принудительно, свои правки выбросить |
| `:checktime` | проверить, изменился ли файл на диске, ничего не выбрасывая |
| `:bufdo e!` | перечитать все открытые буферы |

## Плагины

| Команда | Действие |
| --- | --- |
| `:Lazy` | список плагинов: что загружено, сколько занял старт |
| `:Lazy sync` | поставить новые, удалить лишние, обновить |
| `:Lazy update` | обновить установленные |
| `:Lazy reload имя` | перечитать конфигурацию одного плагина |
| `:Lazy profile` | что именно тормозит запуск |

Версии зафиксированы в `lazy-lock.json` — файл в репозитории, поэтому на другой
машине встанут ровно те же версии. `:Lazy update` его перезаписывает, изменения
видно в git.

## Языковые серверы и инструменты

Ставятся через mason — отдельно от системных пакетов, только для Neovim.

| Команда | Действие |
| --- | --- |
| `:Mason` | интерфейс: что установлено, что доступно |
| `i` / `X` | установить / удалить выбранное |
| `g?` | справка внутри Mason |
| `:MasonInstall имя` | поставить пакет командой |
| `:MasonToolsUpdate` | доустановить всё из списка в конфиге |

Список того, что ставится автоматически, — в `lua/plugins/lsp/mason.lua`.
Настройки конкретного сервера — в `lsp/<имя>.lua`.

**Имя пакета в Mason и имя сервера в конфиге могут отличаться.** Mason ставит
`lua-language-server`, а включается он как `lua_ls`.

Сами языки mason не ставит — только инструменты для редактора. Node через
`fnm`, Python через `uv`, Go системным пакетом.

### Добавить новый язык

1. Найти сервер в `:Mason` и поставить.
2. Добавить его имя в список в `lua/plugins/lsp/mason.lua`.
3. Если нужны особые настройки — создать `lsp/<имя>.lua`.
4. Добавить парсер treesitter в `lua/plugins/treesitter.lua`.
5. При необходимости — форматировщик в `conform.lua`, линтер в `nvim-lint.lua`.

## Диагностика

Вид сообщений об ошибках настраивается в `lua/plugins/lsp/lspconfig.lua`,
вызовом `vim.diagnostic.config`.

Чтобы убрать текст ошибки справа от строки и оставить только значки и
подчёркивание:

```lua
virtual_text = false
```

## Проверка состояния

```vim
:checkhealth
```

Показывает, что не в порядке: не найденные внешние программы, отсутствующие
парсеры, неправильные настройки. Разделы можно смотреть по отдельности:

```vim
:checkhealth lazy
:checkhealth vim.lsp
:checkhealth nvim-treesitter
```

Полезное при разборе проблем:

| Команда | Что покажет |
| --- | --- |
| `:LspInfo` | какие серверы подключены к текущему файлу |
| `:ConformInfo` | какой форматировщик сработает |
| `:messages` | сообщения, которые промелькнули и исчезли |
| `:Lazy profile` | что тормозит старт |

## Отдельная изолированная сборка

Конфигурация, которая не пересекается с рабочей: свои плагины, своё состояние.
Нужна, чтобы пробовать новое, не рискуя тем, в чём работаете каждый день.

Всё держится на переменной `NVIM_APPNAME` — она подставляется вместо `nvim`
во все пути:

| Без переменной | `NVIM_APPNAME=nvim-try` |
| --- | --- |
| `~/.config/nvim` | `~/.config/nvim-try` |
| `~/.local/share/nvim` | `~/.local/share/nvim-try` |
| `~/.local/state/nvim` | `~/.local/state/nvim-try` |
| `~/.cache/nvim` | `~/.cache/nvim-try` |

### Быстро, без dotfiles

```bash
mkdir -p ~/.config/nvim-try
NVIM_APPNAME=nvim-try nvim
```

Так же можно клонировать чужую сборку:

```bash
git clone https://github.com/кто-то/его-конфиг ~/.config/nvim-try
NVIM_APPNAME=nvim-try nvim
```

Минус: каталог лежит в `~/.config` и в репозиторий не попадёт.

### Внутри dotfiles, через stow

```bash
mkdir -p ~/dotfiles/nvim-try/.config/nvim-try
touch ~/dotfiles/nvim-try/.config/nvim-try/init.lua
cd ~/dotfiles && stow nvim-try
NVIM_APPNAME=nvim-try nvim
```

Если пакет нужен и на новой машине — добавить его имя в массив `PACKAGES`
в `install.sh` и `install_dev.sh`.

### Алиас

В `zsh/.config/zsh/aliases.zsh`:

```sh
alias nv-try="NVIM_APPNAME=nvim-try nvim"
```

Проверить, какая конфигурация запущена, можно изнутри:

```vim
:echo $NVIM_APPNAME
```

Пусто — работает основная. Это первое, что стоит смотреть, когда «настройка не
применилась».

### Сколько занимает места

```bash
du -sh ~/.local/share/nvim-try ~/.local/state/nvim-try ~/.cache/nvim-try
du -sh ~/.config/nvim* ~/.local/share/nvim* ~/.local/state/nvim* ~/.cache/nvim*
```

Полноценная сборка с серверами и парсерами — от 500 МБ до полутора гигабайт.

### Как убрать

Сначала служебные каталоги — они восстановятся сами, поэтому той же командой
можно просто переустановить плагины с нуля:

```bash
rm -rf ~/.local/share/nvim-try ~/.local/state/nvim-try ~/.cache/nvim-try
```

Потом сама конфигурация:

```bash
cd ~/dotfiles && stow -D nvim-try     # убрать симлинк
rm -rf ~/dotfiles/nvim-try            # удалить пакет
```

Или, если она лежала прямо в `~/.config`:

```bash
rm -rf ~/.config/nvim-try
```

Последнее — убрать алиас и имя пакета из установочных скриптов.

> `rm -rf` не спрашивает подтверждения. Перед удалением стоит выполнить
> `ls -la ~/.config | grep nvim` и убедиться, что в команде тестовое имя,
> а не `nvim`.
